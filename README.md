# Binance USDT Futures OI Spike Monitor

一个用于监控 Binance U 本位永续合约 Open Interest 在 1m、3m、5m 内突然增长的实时页面。它使用 Binance 官方公开 API，不需要 API Key。

## 功能

- 默认监控 Binance Futures 全部 USDT 永续合约
- 可切换为只监控 24h 成交额最高的高流动性合约
- 计算 1m、3m、5m OI 变化率
- 结合 5m 价格变化、5m 成交量倍数、资金费率、24h 成交额生成信号
- 默认突出 `5m OI 增长 > 3%` 且 `成交量放大 > 1.5x` 的标的
- 记录除“观察”外的所有信号方向，并统计同一币种 1 小时内重复触发次数
- 区分：多头增仓、空头增仓、挤空、挤多、仅OI增长
- 支持阈值配置、搜索、排序、自动刷新
- 后端通过 SSE 向页面实时推送数据
- 显示每行数据年龄，强信号默认只使用新鲜 OI 数据
- 非“观察”信号触发后推送到钉钉群机器人，消息包含关键词“异动”

## 启动

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## 配置

页面顶部可以调整：

- 监控数量：按 24h USDT 成交额从高到低选取
- 全部合约：开启后扫描全部 USDT 永续合约，监控数量设置会暂时不生效
- OI 5m 阈值
- 5m 成交量倍数阈值
- 强信号分数：默认 50 分，达到后会标记为强信号；非“观察”方向会写入“信号方向记录”
- 最大数据年龄：超过后该行会弱化显示，并不会触发强信号
- 启动回填数量：默认只对 24h 成交额靠前的 160 个合约回填历史样本，避免全市场启动太慢
- K线量倍数数量：默认只对 24h 成交额靠前的 120 个合约拉取 1m K线计算精确 5m量倍数，避免 Binance 限流
- 最低 24h 成交额
- 刷新间隔

## 实时性方案

全量合约监控不能简单理解为“527 个币同一秒全部刷新”。Binance 当前公开 OI 接口仍需要按 symbol 请求，所以本工具使用更稳的分层方案：

- 价格、24h成交额：通过 Binance 全市场 ticker 批量获取
- 资金费率：通过 premium index 批量获取
- 当前 OI：按 symbol 并发分片扫描
- 启动回填：首次扫描时会对高成交额合约用 1m K 线回填价格/成交额样本，并用 5m OI 历史接口回填 OI 样本
- 1m/3m OI 变化：Binance OI 历史最小周期偏粗，仍以运行后的实时采样为准
- 5m OI 变化：优先使用启动回填后的 OI 样本计算
- 5m价格变化：对高流动性合约使用 1m K 线和最新价计算
- 5m量倍数：对高流动性合约使用 1m K 线 quote volume 计算，最近 5 根已收盘 K 线成交额 / 前 5 根已收盘 K 线成交额

如果 Binance 返回 `418` 或 `429`，表示当前服务器 IP 被限流或临时封禁。程序会自动退避 5 分钟，避免继续请求加重封禁。
- 数据年龄：每行显示距离最近一次 OI 更新过去了多少秒

如果你追求更强实时性，优先降低刷新秒数到 30-45 秒，并把最大数据年龄设为 60-90 秒。若出现 Binance 限频或超时，再调高刷新秒数。

修改后点击保存，后端会使用新配置重新筛选和计算。

## 信号逻辑

- 多头增仓：OI 增长，价格上涨
- 空头增仓：OI 增长，价格下跌
- 挤空：OI 增长较强，价格快速上涨，资金费率偏正
- 挤多：OI 增长较强，价格快速下跌，资金费率偏负
- 仅OI增长：OI 增长明显，但价格方向不强

信号强度会综合 OI 5m 增长、成交量倍数、价格变化幅度和 24h 成交额计算，范围为 0-100。

## 如何看重复触发

同一币种在 1 小时内多次触发强信号，通常说明市场正在持续关注它，但不代表一定会继续上涨或下跌。

- OI 连续增加、价格沿同一方向推进、成交量持续放大：更像趋势延续
- OI 连续增加、价格高位横盘或快速冲高回落：可能是诱多或多空换手
- OI 增加、价格下跌且反弹弱：更偏空头压制
- OI 突然下降、价格快速反向：可能是平仓或挤压结束

比较稳的使用方式是：先用“信号方向记录”找到反复出现的币，再去 Binance 看 1m/5m K 线确认是否突破关键位置，并设置止损。

## 模拟交易计划

页面内置纸上模拟账户，默认初始资金 10,000 USDT。它不会连接交易所，也不会下真实订单，只用于验证信号是否有正期望。

模拟交易的开仓、平仓记录都会同步推送到钉钉群，消息标题包含“异动”。

默认策略：

- 入场信号：只使用强方向信号
- 做多：多头增仓、挤空
- 做空：空头增仓、挤多
- 跳过：观察、仅OI增长
- 单笔风险：账户权益 1%
- 首仓止损：2%
- 首仓止盈：4%
- 最大持仓：45 分钟
- 止损/反向/超时后冷却：15 分钟
- 止盈后滚仓窗口：10 分钟
- 回踩滚仓：风险降为首仓 50%，滚仓止损 1.5%
- 动量滚仓：风险降为首仓 30%，滚仓止损 1.5%
- 同一趋势最多滚仓：2 次
- 移动止损：盈利 2% 后抬到保本，盈利 3% 后保护最高浮盈的 50%
- 今日亏损停机：当日已实现亏损达到 2% 后停止新开仓
- 连亏暂停：连续亏损 3 笔后暂停新开仓 180 分钟
- 最大同时持仓：5 个
- 模拟手续费：单边 0.05%
- 最大模拟杠杆：3x

山寨币波动通常明显大于 BTC/ETH，1.2%/2.4% 这类止损止盈容易被正常波动扫掉。当前默认改为 2%/4%，但单笔风险仍保持账户 1%，所以止损变宽时模拟仓位会自动变小。

止盈后不会一刀切冷却，而是进入可滚仓状态：如果 10 分钟内出现 0.5%-1.2% 的回踩/反弹且方向继续确认，则用 50% 风险滚仓；如果等不到回踩但 OI、价格、成交量继续顺方向增强，则用 30% 风险动量滚仓。止损、反向信号、超时会进入冷却，避免亏损后继续硬追。

风控停机只会阻止新开仓，已有持仓仍会继续按止损、止盈、移动止损、反向信号和超时规则管理。页面会统计不同信号方向和不同入场类型的胜率、净盈亏、平均盈亏和盈亏因子，用来判断哪些规则值得保留。

建议验证流程：

- 第一阶段：连续跑 3 天，只观察交易记录，不改参数
- 第二阶段：连续跑 7-14 天，统计胜率、盈亏比、最大回撤
- 第三阶段：如果模拟交易数大于 50 笔，且净收益为正、最大回撤可接受，再考虑小资金实盘
- 实盘初期：单笔风险不要超过账户 0.3%-0.5%，连续亏损 3 笔暂停

实盘前最低要求：

- 模拟胜率不低于 45%
- 平均盈利 / 平均亏损大于 1.2
- 最大回撤低于 10%
- 至少跑过一轮震荡行情和一轮趋势行情

## 实盘交易切换计划

当前版本只做模拟交易，不会下真实订单。后续可以接入 Binance Futures API，把同一套策略引擎从 `paper` 模式切换到 `live` 模式，但必须满足以下条件：

- API Key 只开启 Futures 交易权限
- 禁止提现权限
- 建议绑定服务器 IP 白名单
- 实盘初始资金使用小账户，不超过总资金的 5%-10%
- 单笔风险从 0.3%-0.5% 开始，不使用模拟账户里的 1%
- 每日最大亏损达到 2% 自动停机
- 连续亏损 3 笔自动停机
- Binance 返回限流、下单失败、价格异常、网络异常时自动停机
- 所有实盘开仓、平仓、失败、撤单、停机事件同步推送钉钉
- 实盘前至少完成 7-14 天模拟验证，并保留交易记录

实盘下单建议流程：

- 下单前重新获取交易所最新价格和合约规则
- 按 symbol 精度修正数量和价格
- 使用市价或限价保护单开仓
- 开仓后立即挂止损/止盈保护
- 本地记录订单 ID、仓位、止损、止盈和钉钉推送状态
- 每轮轮询校验本地仓位和交易所仓位是否一致

## 钉钉告警

当某个币触发非“观察”的信号方向并写入“信号方向记录”时，后端会同步推送到钉钉群。默认 3 分钟内同一币种不会重复记录和重复推送。

信号方向记录规则：

- 信号方向不是“观察”
- 数据未过期
- 同一币种距离上次记录超过 3 分钟
- 不要求必须是强信号

默认强信号条件：

- 5m OI 增长达到页面配置阈值
- 5m量倍数达到页面配置阈值
- 强度达到页面配置阈值
- 数据未过期

钉钉机器人设置了关键词时，关键词需要出现在标题或正文里。本项目推送标题包含“异动”。

## 注意

- 1m、3m、5m OI 变化依赖本地运行时滚动采样。刚启动时会使用已采集到的最早样本估算，运行 5 分钟后完整。
- 全部合约模式请求量更大，默认刷新间隔为 45 秒。如果出现限频或网络不稳，可以调高刷新秒数，或者关闭全部合约改用高流动性模式。
- Binance 公共接口在部分网络或地区可能不可用；页面右上角会显示后端拉取状态。
- 这是交易机会监控工具，不构成投资建议。
